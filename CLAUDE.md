@AGENTS.md

## Stack
- **Next.js 16** (App Router) + **React 19**, strict TypeScript (`tsconfig.json` has `strict: true` — keep it that way, no `any`)
- **Tailwind CSS 4** — theme via CSS variables (light/dark), plus a spacing/radius scale
- **Auth.js** — source of identity and sessions (canonical `userId`)
- **Firebase**: Firestore (data), Firebase Storage (product images), **Firebase Admin SDK — server-side only**
- **Stripe Checkout**, test mode, real integration (not mocked) + signature-verified webhooks
- **Axios** for HTTP, **TanStack Query (React Query)** for server-state
- Package manager: **bun** (`bun.lock`, `packageManager: bun@1.3.14`)
- ESLint via `eslint-config-next` (core-web-vitals + typescript)

## Architecture
- Routing lives in `app/` (App Router segments).
- Reusable logic/UI lives in `src/`, per `specs/mvp-scope.md`:
  ```
  src/
    shared/
      components/   # atoms, molecules, ...
      hooks/
      utils/
      index.ts
    modules/
      admin/
      auth/
      ...            # one module per feature area
  ```
- Firestore collections: `products` (standalone + composite/bouquet via `isComposite`+`components`), `users`, `orders` — see `specs/data-model.md` for full field list.

## Key conventions
- Mobile-first, responsive layouts everywhere.
- Prices stored/handled as **minor units (cents)**, currency AUD.
- Order `items` are a **snapshot** of name/price at purchase time — never re-derived from the live product doc.
- Data fetching goes through Axios + React Query, not ad-hoc `fetch`/`useEffect`.
- Admin authorization is **never UI-only**: every admin action checks session + `role === 'admin'` server-side.
- Order ownership (`orders.userId`) is checked server-side — a customer can never fetch another customer's order.
- Stripe webhook is the only source of truth for payment status (`Paid`/`Failed`); the checkout redirect is never treated as proof of payment. Webhook processing is idempotent via `processedStripeEventIds`.

## Protected files
- `AGENTS.md`'s `<!-- BEGIN:nextjs-agent-rules -->` block — auto-regenerated by `next dev`; never edit/remove, always commit as-is.
- `specs/*.md` — source-of-truth specs; treat as read-only reference, don't edit without the user explicitly asking to change a spec.
- `.env*` files — never read their contents into a response, never commit.
- `next-env.d.ts` — auto-generated, don't hand-edit.

## Security rules
- **Firebase service-account / Admin SDK credentials**: server-side code only (Route Handlers, Server Actions, Server Components). Never in a Client Component, never behind `NEXT_PUBLIC_*`.
- **Stripe secret key**: server-side only, never `NEXT_PUBLIC_*`. Only the Stripe **publishable** key is client-safe.
- Stripe webhook handler must verify the signature against the **raw** request body before trusting any event.
- No secrets ever get echoed into chat, logs, or committed files.
